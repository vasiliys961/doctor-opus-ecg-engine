Исходная точка инференса: `analysis_scripts/predict_csv.py`, функция `analyze()`. Веб-обёртка: `app.py` (Flask, порт 5002). `config.py` пустой.

Приложение принимает CSV признаков и возвращает 24 оценки. Извлечение признаков из raw ECG в этом репозитории отсутствует.

## 1. Контракт входа

Анализируется только первая строка CSV, даже если строк несколько.

Колонка `ecg_id`, если она есть, исключается из признаков. Остальных колонок должно быть ровно 531. Имена колонок модель не читает: в сеть попадает порядок столбцов после отбрасывания `ecg_id`. Любая перестановка ломает соответствие весам и `ecg_train_mean.npy` / `ecg_train_std.npy`.

Проверенный файл схемы: `templates/another_ecg_features.csv`.

- 532 колонки: `ecg_id` + 531 признак
- 1 строка данных, `ecg_id = 513`

`templates/sample_ecg_features.csv` и `templates/ECG.csv` содержат 61 колонку (fiducial-метки по 12 отведениям) и текущим анализатором отвергаются. Парного raw ECG рядом с 531-вектором в репозитории нет.

## 2. Схема 531 признака

README прямо называет формат `ecgdeli`. Кода ECGDeli, описания формул и единиц в репозитории нет. Ниже зафиксировано то, что следует из имён колонок и одной эталонной строки. Формулы расчёта этим аудитом не подтверждены: это задача `docs/FEATURE_531_SPEC.md` на следующем этапе.

Каждый признак хранится тройкой по одному измерению:

1. значение без суффикса;
2. тот же stem + `_iqr`;
3. тот же stem + `_count`.

Порядок внутри измерения: value, iqr, count. Затем следующее отведение.

Порядок отведений, где измерение есть на всех 12:

`I, II, III, V1, V2, V3, V4, V5, V6, aVF, aVL, aVR`

Если есть глобальный агрегат, он идёт последним. Имя глобальной оси записано с двумя подчёркиваниями: `HA__Global`, `HA__Global_iqr`, `HA__Global_count`. Остальные глобальные колонки используют один `_`: например `RR_Mean_Global`.

Счётчик семейств:

| Семейство | Отведения | Колонок | Группа |
| --- | --- | ---: | --- |
| `PQ_Int` | 12 + Global | 39 | интервал, P/QRS, fiducial |
| `PR_Int` | 12 + Global | 39 | интервал, P/QRS, fiducial |
| `P_Amp` | 12 | 36 | амплитуда, P, fiducial |
| `P_DurFull` | 12 | 36 | длительность, P, fiducial |
| `P_Dur` | только Global | 3 | длительность, P, несколько отведений |
| `P_Morph` | 12 | 36 | морфология, P, fiducial |
| `Q_Amp` | 12 | 36 | амплитуда, QRS, fiducial |
| `QRS_Dur` | 12 + Global | 39 | интервал, QRS, fiducial |
| `QT_IntCorr` | 12 | 36 | корригированный интервал, T/QT, fiducial |
| `QT_IntFramingham` | только Global | 3 | корригированный интервал, несколько отведений |
| `QT_Int` | 12 + Global | 39 | интервал, T/QT, fiducial |
| `R_Amp` | 12 | 36 | амплитуда, QRS, fiducial |
| `RR_Mean` | только Global | 3 | ритм / RR, несколько отведений |
| `S_Amp` | 12 | 36 | амплитуда, QRS, fiducial |
| `ST_Elev` | 12 | 36 | амплитуда ST, fiducial |
| `T_Amp` | 12 | 36 | амплитуда, T, fiducial |
| `T_DurFull` | 12 | 36 | длительность, T, fiducial |
| `T_Dur` | только Global | 3 | длительность, T, несколько отведений |
| `HA` | только Global | 3 | ось, несколько отведений |

Итого: `4×39 + 10×36 + 5×3 = 531`.

`_count` на эталонной строке лежит в диапазоне 1…12 и по смыслу имени является числом комплексов, вошедших в агрегат, а не клиническим классом. `_iqr` — разброс этого измерения между комплексами.

На строке `ecg_id=513` интервалы выглядят как миллисекунды (`PQ_Int_II=146`, `QRS_Dur_II=114`, `QT_Int_II=395`, `RR_Mean_Global=862`), амплитуды Q/R/S/P/T — как милливольты (`R_Amp_II=0.975`, `Q_Amp_II=-0.14`). Единицы в коде не заданы. `PQ_Int_II=146` и `PR_Int_II=202` различаются, это разные колонки. `P_Morph_II=1` и `HA__Global=2` выглядят как коды, не как миллисекунды и не как угол в градусах. Формула `QT_IntCorr` по одной строке не совпала с Bazett от медианы QT и RR; пока экстрактор не найден, коррекцию QT воспроизводить по названию нельзя.

Все 531 измерения зависят от fiducial points (начала и концы P, QRS, T), кроме того что глобальные величины ещё сворачивают несколько отведений. В репозитории нет функции, которая считает эти величины из сигнала.

61-колоночные CSV — это другой объект: `ecg_id` плюс `p_onset`, `p_offset`, `qrs_onset`, `qrs_offset`, `t_offset` для 12 отведений. Это разметка границ, не вход сети.

## 3. Нормализация

Файлы:

- `models/ecg_train_mean.npy` — `float64`, shape `(1, 531)`
- `models/ecg_train_std.npy` — `float64`, shape `(1, 531)`

Формула, в этом порядке:

1. `NaN` в строке заменяется на соответствующее значение `train_mean` (после z-score эти позиции становятся 0).
2. `+Inf` → `1e6`, `-Inf` → `-1e6`.
3. `X = (X - train_mean) / train_std`. Деление идёт с broadcasting `(1, 531)`.
4. Если после деления снова появились `NaN` или `Inf`, они заменяются на `0`, `1e6`, `-1e6`.

Нулевой `std` в сохранённом файле нет: минимум `std` около `0.056`. Две колонки уже пришли с `std = 1`, что совпадает с комментарием в коде «нулевой std заменён единицей при сохранении»:

| Индекс | Колонка | mean | std |
| ---: | --- | ---: | ---: |
| 529 | `HA__Global_iqr` | 0 | 1 |
| 530 | `HA__Global_count` | 1 | 1 |

Порядок колонок mean/std обязан совпадать с порядком CSV.

## 4. Архитектуры

Общее: 24 логита, без сигмоиды внутри сети. Функция потерь, под которую собраны головы, в коде названа `BCEWithLogitsLoss`. Инференс принудительно на CPU. Dropout при `eval()` выключен, BatchNorm использует running stats. Это нужно сохранить для regression test.

Веса загружаются как сырой `state_dict`, либо из ключей `state_dict` / `model_state_dict`. Префикс `net.` снимается. В текущих трёх файлах префикса `net.` нет: это сразу `OrderedDict` с именами слоёв.

### MLP — `models/ecg_model.pth` (711 KB, сохранён на CPU)

`nn.Sequential`, вход `(N, 531)`:

| Индекс | Слой |
| ---: | --- |
| 0 | `Linear(531, 256)` |
| 1 | `ReLU` |
| 2 | `BatchNorm1d(256)` |
| 3 | `Dropout(0.5)` |
| 4 | `Linear(256, 128)` |
| 5 | `ReLU` |
| 6 | `BatchNorm1d(128)` |
| 7 | `Dropout(0.4)` |
| 8 | `Linear(128, 64)` |
| 9 | `ReLU` |
| 10 | `Dropout(0.3)` |
| 11 | `Linear(64, 24)` |

Ключи чекпоинта совпадают с этой нумерацией: `0.weight`, `2.weight`, `4.weight`, `6.weight`, `8.weight`, `11.weight` и соответствующие `bias` / `running_mean` / `running_var`.

### 1D CNN — `models/ecg_1dcnn_best.pth` (17 MB, сохранён с `cuda:0`)

Вход `(N, 1, 531)`. Класс `ECG1DCNN`.

`features`:

| Индекс | Слой |
| ---: | --- |
| 0 | `Conv1d(1, 64, kernel=7, padding=3)` |
| 1 | `BatchNorm1d(64)` |
| 2 | `ReLU` |
| 3 | `MaxPool1d(2)` |
| 4 | `Dropout(0.2)` |
| 5 | `Conv1d(64, 128, kernel=5, padding=2)` |
| 6 | `BatchNorm1d(128)` |
| 7 | `ReLU` |
| 8 | `MaxPool1d(2)` |
| 9 | `Dropout(0.3)` |
| 10 | `Conv1d(128, 256, kernel=3, padding=1)` |
| 11 | `BatchNorm1d(256)` |
| 12 | `ReLU` |
| 13 | `AdaptiveAvgPool1d(32)` |

`classifier`: `Linear(8192, 512)` → `ReLU` → `Dropout(0.5)` → `Linear(512, 128)` → `ReLU` → `Dropout(0.3)` → `Linear(128, 24)`.

Ключи `features.0`, `features.5`, `features.10`, `classifier.0`, `classifier.3`, `classifier.6` совпадают с этой схемой. Размер файла согласован с матрицей `256×32×512`.

### ResNet1D — `models/ecg_resnet1d_features_best.pth` (15 MB, сохранён с `cuda:0`)

`resnet18_1d`: `ResNet1d(ResidualBlock1d, [2, 2, 2, 2])`, вход `(N, 1, 531)`.

Ствол:

- `Conv1d(1, 64, kernel=7, stride=2, padding=3, bias=False)` + `BatchNorm1d` + `ReLU`
- `MaxPool1d(kernel=3, stride=2, padding=1)`
- layer1: 64 канала, 2 блока
- layer2: 128, stride 2
- layer3: 256, stride 2
- layer4: 512, stride 2
- `AdaptiveAvgPool1d(1)` → `Linear(512, 24)`

Блок: две `Conv1d` kernel 3, padding 1, без bias, BatchNorm и ReLU между ними; residual складывается до финального ReLU. Downsample — `Conv1d` 1×1 со stride и BatchNorm, когда меняется число каналов или stride.

В чекпоинте есть `conv1.weight`, `bn1.*`, `layer1.0.conv1`, `layer1.1`, `layer2.0` и далее по той же схеме. Префикса `net.` нет.

## 5. Ансамбль

`get_ensemble_predictions`:

1. Для каждой успешно загруженной модели считается `sigmoid(logits)`.
2. Массивы усредняются с равными весами: `np.mean(..., axis=0)`.
3. Отдельные головы в HTTP/HTML-ответ не попадают. Наружу уходит только среднее.

Если одна модель не загрузилась, среднее считается по оставшимся, без флага деградации. Для regression test эталоном считается полный состав MLP + CNN + ResNet. В новом движке нужно сохранять сырые выходы всех трёх голов и ensemble отдельно, как требует ТЗ, но базовый ensemble-вектор для сверки с `ecg_web_up` должен совпадать с нынешним средним.

Модели создаются заново на каждый вызов `analyze()`. В новом сервисе их нужно загрузить один раз при старте, не меняя численный результат.

## 6. Порог

Порога решения нет. Все конечные 24 значения возвращаются и сортируются по убыванию. `NaN` и `Inf` в вероятности выкидывают соответствующий код из списка, а не заменяют его нулём.

В `templates/results.html` колонка подписана «Вероятность» и печатается с 4 знаками. Это сигмоида усреднённых логитов. Клинической калибровки в репозитории нет. В новом интерфейсе ту же величину нужно показывать как model score / neural network output.

| 23 | AMI | Острый инфаркт миокарда (передняя стенка) |

Элемент результата: `{code, ru_name, probability}`. Список отсортирован по убыванию score, поэтому позиция в ответе не равна индексу головы. Для regression test нужно сравнивать вектор до сортировки, по индексу `TOP_24_CODES`.

Подписи не влияют на тензор. Несколько из них расходятся с формулировками SCP в PTB-XL, откуда этот набор кодов обычно берётся:

- `SARRH` в PTB-XL — sinus arrhythmia; в коде — «синусовый ритм с аберрантным проведением».
- `ISCAL` в PTB-XL — ischemic in anterolateral leads; в коде — ишемия нижней стенки.
- `VCLVH` в PTB-XL — voltage criteria (LVH); в коде формулировка шире.
- `AMI` в PTB-XL — anterior myocardial infarction; слово «острый» в коде добавлено переводчиком.

Индекс модели менять нельзя. Русские подписи в новом движке стоит сверить с исходной таблицей SCP до того, как они попадут в отчёт.
